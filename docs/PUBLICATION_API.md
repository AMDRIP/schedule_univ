# Публикация расписания, календари и Telegram

## Версии в приложении

Раздел «Публикация расписания» доступен администратору и методисту.

1. Подготовьте рабочее расписание. Укажите название версии, комментарий и часовой пояс (по умолчанию `Europe/Samara`).
2. Нажмите «На согласование». Сохраняется независимый снимок черновика и подписей справочников. В сравнении видны добавления, отмены, переносы, замены преподавателей и аудиторий, затронутые группы.
3. Нажмите «Опубликовать». Общий валидатор повторно проверяет занятия, включая недельные шаблоны, занятость, переходы и жёсткие правила. При изменении черновика или исходных данных после согласования требуется новый снимок.
4. Сохраните проект. История входит в `.schd` и JSON-резервную копию (схема 4); старые проекты открываются без публикаций. При объединении проектов чужая история не подменяет действующую публикацию.

Рабочая сетка методиста остаётся черновиком. Роли студента и преподавателя показывают опубликованный снимок. Переключение роли в desktop-интерфейсе не является аутентификацией пользователя или системой совместного согласования.

Публикуются все датированные занятия сохранённой сетки, включая сессию за границами учебного семестра; фактический период показан в карточке версии. Недельные шаблоны разворачиваются только в границах семестра и не продлеваются автоматически на сессию. Историю учебных лет длиной более двух лет нужно разделить на проекты перед публикацией.

Новая публикация архивирует предыдущую. «Восстановить в черновик» возвращает занятия выбранной версии, не меняя действующую публикацию. Справочники не откатываются: восстановленную сетку нужно проверить, отправить на согласование и опубликовать под новым номером. Это сохраняет монотонность версий для интеграций.

## Граница публичных данных

API, JSON публикации и ICS содержат только опубликованные общегрупповые занятия: дисциплину, время, вид занятия, группы/подгруппу, преподавателей и аудиторию. Конкретные студенты, индивидуальные записи, работы, оценки, номера зачётных книжек, заметки, ограничения доступности, пути файлов и ключи доступа не передаются. Занятия с конкретным составом `studentIds` и события научных работ исключаются целиком, а не обезличиваются с потерей смысла.

Имена преподавателей и обозначения групп остаются в публикации. Перед передачей за пределы университета проверьте допустимость публикации этих сведений. Передавать боту `.schd` нельзя: это полный внутренний проект.

## Локальный API настольного приложения

Во вкладке «API и календари» запустите сервис. По умолчанию адрес: `http://127.0.0.1:8597`. При занятом порте выберите другой.

- Сервис выключен при запуске приложения, не открывает порт во внешнюю сеть и не создаёт правил брандмауэра.
- Остановка и повторный запуск меняют ключи. Ключи живут только в памяти главного процесса, не попадают в проект и логи.
- Смена проекта останавливает сервис. Черновые изменения не меняют его данные; новая публикация обновляет их без перезапуска.
- Доступны только `GET`; без ключа выдаётся `401`, попытка записи получает `405`. CORS для внешних сайтов не включён.
- Пока приложение закрыто, встроенный сервис не работает. Для отдельного сервера предусмотрен запуск ниже.

Ключ API передаётся заголовком `Authorization: Bearer <ключ>`:

| Маршрут | Результат |
| --- | --- |
| `/api/v1/status` | Проект, версия, часовой пояс и период публикации |
| `/api/v1/groups` | Опубликованные группы: стабильный ID и название |
| `/api/v1/teachers` | Преподаватели опубликованных групповых занятий |
| `/api/v1/classrooms` | Аудитории опубликованных занятий |
| `/api/v1/schedule?groupId=ID&from=2026-10-19&to=2026-10-25` | Занятия выбранной группы и периода |
| `/api/v1/changes?projectId=ID&since=1&groupId=GROUP` | Добавления, отмены и изменения относительно версии 1 |

Фильтры `teacherId` и `classroomId` работают аналогично `groupId`. Даты включительны. Для изменений учитываются обе стороны переноса: занятие, ушедшее из выбранной группы или периода, не исчезает из отчёта незаметно. `since=0` означает пустую исходную сетку. Если проект сменился или версия не найдена, ответ `409` с `resyncRequired: true` требует заново загрузить расписание. ETag позволяет получить `304` при неизменном результате, но не отменяет авторизацию.

Контракт имеет `schemaVersion: 1`; проект и сущности идентифицируются ID, а не названиями. Это основа для бота, сайта и будущей системы успеваемости. API не предоставляет прав на изменение проекта.

## ICS

Опубликованную сетку можно скачать как `.ics`. Для подписки скопируйте адрес календаря во вкладке API. В нём отдельный ключ `token`, пригодный только для `/calendar.ics`, но не для JSON API. Этот адрес даёт доступ к опубликованным групповым расписаниям; его нужно хранить как секрет. Фильтр группы удобен для просмотра, но не является разграничением доступа.

События имеют стабильные UID, номер версии в SEQUENCE, реальные даты и время UTC, вычисленное из выбранного часового пояса. Сокращённые и особые звонки берутся по дате занятия. Частота обновления подписки зависит от календарного клиента. Ссылки на `127.0.0.1` работают только на том же компьютере; для телефона потребуется отдельно настроенный HTTPS-сервер.

## Telegram из приложения

Встроенный бот работает в настольном приложении без PowerShell, отдельного Node.js и ручного запуска API. Он читает тот же опубликованный снимок напрямую и использует официальный [Telegram Bot API](https://core.telegram.org/bots/api) через исходящие HTTPS-запросы, без входящего webhook и открытого внешнего порта.

1. Создайте бота через [BotFather](https://core.telegram.org/bots/tutorial#obtain-your-bot-token). Токен вводите только в поле приложения, не отправляйте его студентам, в чаты или исходники.
2. Опубликуйте расписание в разделе «Публикация расписания» и сохраните проект.
3. Откройте раздел «Telegram-бот» слева или одноимённую вкладку публикации. Вставьте токен и нажмите «Сохранить настройки».
4. Нажмите «Проверить подключение», затем «Запустить бота». После успешного подключения появятся статус «Подключён» и ссылка на бота.
5. Отправьте студентам ссылку. В личном чате они нажимают «Старт», выбирают группу кнопкой или пишут её название, затем открывают день или неделю. Преподаватель и аудитория выбираются аналогично.
6. Для последующих запусков включите «Автозапуск вместе с приложением» и сохраните настройки. После запуска приложения бот дождётся загрузки проекта с опубликованной версией. Это не автозапуск Windows: закрытое приложение и выключенный компьютер запросы не обслуживают. «Остановить бота» действует до ручного запуска или следующего старта приложения.

Токен хранится зашифрованным через [Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage) в `telegram-settings.json` каталога данных приложения. Он не входит в SCHD, JSON проекта, публичную публикацию и ответы статуса. Если защищённое хранилище ОС недоступно, сохранение токена отменяется, а не заменяется открытым текстом. На Windows защита привязана к учётной записи ОС; это не защита от других программ, уже работающих от её имени. При переносе на другой компьютер или учётную запись введите токен заново. «Удалить токен» останавливает сервис и отключает его автозапуск, но не удаляет подписки.

Настройки ответов: выделение текста или обычный текст, подробный/компактный вид, показ преподавателей и аудиторий. Предпросмотр использует тот же форматировщик, что бот. Каждому дню посвящено отдельное сообщение; длинные дни делятся без разрыва HTML-разметки. Кнопки позволяют листать дни/недели, искать по названию и подписываться на изменения. ID ресурсов не показываются в обычных списках.

При потере сети отображается «Переподключение» с автоматическим повтором. Если бот уже работает в PowerShell или на другом сервере, сначала остановите прежний экземпляр: одновременно два `getUpdates` с одним токеном не работают. Настроенный ранее webhook нужно отключить в прежнем сервисе или создать другого бота; приложение не удаляет чужие настройки автоматически. Для работы нужен исходящий HTTPS-доступ к `api.telegram.org`.

Выбор, offset и подписки хранятся отдельно от проекта в `telegram-state-IDБОТА.json` каталога данных приложения. Там нет токена, но есть chat ID, выбранный ресурс и версия, поэтому файл внутренний. `/forget` удаляет выбор и подписку пользователя. Подписки включаются только по явному действию в чате. Это публичное групповое расписание, не авторизация студента; индивидуальные записи и успеваемость через этот бот недоступны.

## Дополнительный запуск бота вне приложения

Этот вариант оставлен для отдельного сервера и разработки. Нужен Node.js 22 или новее и запущенный read-only API. В PowerShell задайте переменные окружения в своей сессии:

```powershell
$env:TG_BOT_TOKEN = '<токен BotFather>'
$env:SCHEDULE_API_TOKEN = '<ключ API из приложения>'
$env:SCHEDULE_API_URL = 'http://127.0.0.1:8597'
npm run start:bot
```

В этом варианте токен берётся из окружения и не сохраняется CLI. Не запускайте его одновременно со встроенным ботом на том же токене. Для автоматических тестов используются подставные ответы; реальный бот без пользовательского токена не запускается.

Кроме кнопок, доступны команды: `/groups [поиск]`, `/group название_или_ID`, `/teachers [поиск]`, `/teacher имя_или_ID`, `/rooms [поиск]`, `/room номер_или_ID`, `/today`, `/tomorrow`, `/week`, `/nextweek`, `/changes`, `/subscribe`, `/unsubscribe`, `/forget`.

Каркас отвечает в личных чатах. Подписки включаются только командой пользователя. Уведомления показывают изменения выбранного объекта с «Было / Стало», не реагируют на чужие изменения и не рассылаются повторно для уже обработанной версии. При смене проекта выбор сбрасывается. Дата определяется по часовому поясу публикации, а не по часовому поясу сервера.

В CLI по умолчанию создаётся `telegram-state-IDБОТА.json` в рабочем каталоге. Путь можно задать через `SCHEDULE_BOT_STATE`, в том числе для переноса прежнего `.telegram-bot.local.json`. Offset и подписки проверяются перед использованием; повреждённый файл не перезаписывается пустым. Не запускайте два экземпляра с одним токеном или файлом состояния.

При аварии между отправкой сообщения и сохранением состояния возможна повторная доставка. Каркас не обещает exactly-once; это не система гарантированной рассылки.

Для работы бот должен оставаться запущенным и иметь исходящий HTTPS-доступ к Telegram. В минимальном варианте он работает на компьютере методиста вместе с приложением; выключенный компьютер не обслуживает запросы. Сам каркас не оплачивает хостинг и не подключает платные API.

## Отдельный сервис

Экспортируйте `published-schedule.json` во вкладке API. Для чтения без Electron:

```powershell
$env:SCHEDULE_PUBLICATION_FILE = 'Y:\UNIV\published-schedule.json'
$env:SCHEDULE_API_TOKEN = node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
$env:SCHEDULE_CALENDAR_TOKEN = node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
npm run start:api
```

Сервис перечитывает только экспорт публикации каждые 3 секунды. Повреждённый или удалённый файл приостанавливает выдачу данных, не превращается в пустое успешное расписание. Для обновления замените экспорт новым. Встроенный API не требует ручного экспорта.

Оба сервиса по умолчанию доступны только на loopback. Доступ извне, HTTPS, учётные записи и развёртывание за обратным прокси являются отдельной задачей эксплуатации. Не открывайте служебный ключ в публичном браузерном JavaScript. Бот разрешает HTTP только для loopback, для удалённого адреса требует HTTPS и не пересылает ключ при редиректе.
